# Artist-Scoped Caption & Tag Generation (specified, not yet implemented)

This document specifies a toolkit feature; there is no code behind it yet. It lives
here rather than inside the annotation guide because the two `updated_*_instruct.txt`
reference files already describe the intended LLM behaviour, and a requirement that
only exists in loose notes is a requirement that will drift. Nothing in this document
changes any annotation rule — it is a generation aid built on the rules in
[`Comprehensive_LoRA_LoKR_Dataset_Annotation_Guide_updated.md`](Comprehensive_LoRA_LoKR_Dataset_Annotation_Guide_updated.md)
(section references below point there unless stated otherwise).

## 1. Purpose

Given a dataset scoped to one artist or band, produce (a) a caption *template* and (b)
a lyric-bracket *template* that stay consistent across every track in that dataset,
drawn from that artist's own descriptor faceting rather than one generic list.

The problem it solves is annotation drift: when each track is annotated independently
from a generic vocabulary, the same feature gets named three different ways across a
twelve-track dataset. Annotation guide §8 explains why training will not repair that —
only the attention projections adapt and the text encoder is frozen — so the dataset
has to be internally consistent by construction. A template makes consistency the
default instead of an act of discipline.

## 2. Inputs

| Input | Required | Notes |
|---|---|---|
| Artist / band name | yes | Loose forms must resolve: `sabbath`, `Doorsdata`, `hank_sr` |
| Trigger tag | yes | Dataset-level, e.g. `acdc_bon`; identical in every caption (annotation guide §7) |
| Optional per-track facts | no | BPM, key, duration, instruments, structural segments — supplied by `modules/tag_creator.build_track_context` |

## 3. Vocabulary resolution (reuse the existing code)

Do **not** build a second vocabulary mechanism. The resolver already exists:

- `modules/vocabulary.resolve_artist(groups, artist)` — word-based loose matching, so
  real folder names resolve.
- `modules/vocabulary.terms_for_artist(groups, artist)` — returns
  `(artist_facets, general_facets, resolved_name)`, falling back to the cross-artist
  fundamentals only, never to another artist's signature terms.

Data files, all hand-maintained and present in `docs/`: `vocabulary.json` (artist-scoped
facets, preferred), `vocabulary.txt` (flat fallback), `section_markers.txt` (the legal
`[Marker]` names), `descriptor_reference.md` (the prose standard).

## 4. Output shape

Both templates are text intended to be handed to the annotation LLM, not finished
annotations:

1. **Caption template** — the fixed prefix (`<trigger_tag>, `), then the artist's facet
   slots in a stable order (genre → mood/energy → instruments → vocal character →
   production/era), then the comma-separated fact tail of annotation guide §1
   (8–16 acoustic facts, no prose sentences). The
   order is fixed deliberately: position then carries signal, and a consistently
   ordered caption is easier for the adapter to read than a shuffled one.
2. **Lyric bracket template** — the legal `[Marker]` set from `section_markers.txt`, the
   per-bracket descriptor slots (count per §7 below), and the language-first form
   (`[EN - Chorus - anthemic]`) for non-English tracks.

## 5. Guardrails (carry these into any implementation)

- **The vocabulary is an *invocation* list, not a validation list.** It steers a
  generation prompt. It must never gate what a *training* annotation is allowed to say,
  and must never be used to reject a caption or a bracket. See `modules/vocabulary.py`
  and annotation guide §1.
- **Do not name the same feature in both streams.** CFG dropout removes the caption
  *and* the lyrics together (annotation guide §8; mechanism in
  [`LoRA_LoKR_Creation_Guide.md`](LoRA_LoKR_Creation_Guide.md) §7), so duplicating a
  feature across the two streams buys no robustness and costs you a clean on/off
  trigger.
- **A respelling must not produce a real English word.** Any Tier 2 contraction
  respelling (annotation guide §4.6) generated by a profile must not collide with a
  dictionary word — `well → weel`, never `heel`; `I'd → eye-d`, never `eyed`. A
  homophone re-creates exactly the ambiguity the respelling exists to remove.
- **Omit what is constant.** Whatever appears on essentially every track in the dataset
  belongs in the trigger tag and must not be repeated in either stream (annotation
  guide §1.1).

## 6. Where it plugs in

`modules/tag_creator.py` already assembles the prompt context and loads the vocabulary
files and the markers. The feature is a template generator layered on top of
`load_vocabulary()` and `load_markers()`: same data, same resolution, new output shape.
It must not introduce a third vocabulary path.

## 7. The open item this specification cannot settle

How many descriptors a bracket may carry. `docs/ACE_Step_1.5_Master_Annotation_Guide.md`
§3 says "maximum 3"; the songwriting skill says 1. That is an unresolved decision, not a
settled rule, so the template generator must be parameterised on it rather than
hard-coding either number.
